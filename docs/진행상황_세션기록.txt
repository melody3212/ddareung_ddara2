5. 환경변수 (.env — 커밋 금지)
--------------------------------------------------------------------------------
[backend/.env]
  CORS_ORIGINS=http://localhost:5173,http://127.0.0.1:5173,http://192.168.219.123:5173
  SEOUL_OPENAPI_KEY=...   (따릉이 대여소, 실측 시 수천 건)
  KAKAO_REST_KEY=...      (장소 검색, places source=kakao 확인됨)
  (선택) SAFEMAP_SERVICE_KEY, WEATHER_API_KEY, AIR_API_KEY

[frontend/.env]
  VITE_API_BASE_URL=/api
    → Vite 프록시로 백엔드 연결 (폰에서도 동일 출처라 유리)
  VITE_KAKAO_JS_KEY=...   (지도 JS SDK)

카카오 REST 키는 대화 중 붙여넣어 backend/.env 에 설정함.
채팅에 노출됐으므로 나중에 재발급 권장.


6. 로컬 실행 방법 (PC)
--------------------------------------------------------------------------------
# 백엔드 (LAN/폰 대비 0.0.0.0)
cd backend
.\.venv\Scripts\python.exe -m uvicorn app.main:app --host 0.0.0.0 --port 8000

# 프론트
cd frontend
npx vite --host 0.0.0.0 --port 5173

PC 접속:
  http://localhost:5173
  http://127.0.0.1:5173

API 프록시:
  frontend/vite.config.ts 에 /api → http://127.0.0.1:8000
  client: VITE_API_BASE_URL 없으면 기본 '/api'


7. 휴대폰에서 접속 (중요 — 미해결/부분해결)
--------------------------------------------------------------------------------
PC Wi-Fi IP 예시: 192.168.219.123
SSID: U+Net560B_5G
네트워크 프로필: Public (공용) ← 폰 직접 접속 실패 원인으로 추정

[시도한 것]
  - 백엔드 --host 0.0.0.0
  - 프론트 host true + /api 프록시
  - CORS에 LAN 주소 추가
  - 방화벽 포트 규칙 추가 시도 → 관리자 권한 없어 실패
  - 네트워크 Private 전환 시도 → 권한/정책으로 실패
  - Cloudflare quick tunnel 사용

[터널 방식 — 당시 주소, 재시작 시 변경됨]
  https://makers-locale-ensemble-integrated.trycloudflare.com
  실행 예:
    npx cloudflared tunnel --url http://127.0.0.1:5173
  장점: 방화벽 우회, HTTPS → GPS 유리
  단점: 주소 매번 바뀜, 카카오 Web 도메인 재등록 필요

[LAN 직접 접속을 살리려면 — 관리자 PowerShell 한 번]
  Set-NetConnectionProfile -InterfaceAlias "Wi-Fi" -NetworkCategory Private
  netsh advfirewall firewall add rule name="Ddareung-5173" dir=in action=allow protocol=TCP localport=5173 profile=any
  netsh advfirewall firewall add rule name="Ddareung-8000" dir=in action=allow protocol=TCP localport=8000 profile=any
  폰: http://192.168.219.123:5173
  카카오 Web 도메인: http://192.168.219.123:5173 추가

[GPS 참고]
  http://192.168.x.x 는 secure context 가 아니라 일부 폰에서 위치 거부
  HTTPS 터널이면 주행 GPS 가능성 높음
